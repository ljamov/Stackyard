WordPress

From live to local, and back again

Copy a live WordPress or WooCommerce site to your computer over SSH, SFTP or FTP, or from a hosting panel backup. Stackyard reads the database login from the live wp-config.php, changes every address to the local one, sends mail to Mailpit and puts payments into test mode. Try changes on a staging copy, merge them back, and push to live: the live database and every changed file are backed up first, the maintenance page shows while it works, and if a step fails the backup goes back by itself.

WordPress guide →

# copy a live site, then make a staging copy
$ stackyard wp clone shop --host example.com --user me
$ stackyard wp staging new checkout --site shop.stack

# merge it back into shop.stack
$ stackyard wp staging merge checkout.shop.stack --yes

# see what a push would send, then send it
$ stackyard wp push shop.stack
$ stackyard wp push shop.stack --yes

AI-ready

Let your AI coding tool see your stack

Stackyard has a built-in MCP server for Claude Code, Cursor, Claude Desktop, Windsurf and others. AI tools can list sites, services, runtimes and databases and read logs. Starting and restarting services, creating sites, changing versions and running SQL stay off until you allow them, and deleting sites, whole databases or files is never offered. Every call is logged.

# connect Claude Code to Stackyard
$ claude mcp add --scope user stackyard -- stackyard mcp

# allow one action
$ stackyard mcp allow start_service

# see what AI tools did
$ stackyard mcp log
$ stackyard system setup        # domains and HTTPS
$ stackyard sites park ~/Code   # every folder is a site
$ stackyard runtimes install php 8.4
$ stackyard use php 8.3         # pin this project
$ stackyard start               # run it all
